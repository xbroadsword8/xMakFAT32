## 四、程式碼品質檢查

### 4.1 安全性

| 檢查項目 | 狀態 | 說明 |
|----------|------|------|
| `unsafe` 使用 | 最小化 | 僅限於 Win32 API 原生系統呼叫（GUI 層）。磁碟結構（MBR, Boot Sector, FSInfo, DirEntry）的二進位序列化與反序列化已完全導入 `zerocopy` 安全轉換，實現 100% 安全（Safe Rust）防護。 |
| 邊界溢位 | 已修正 | `Mbr::new()` 使用 u64 參數，截斷到 u32::MAX；`MAX_BYTES` 為 `(u32::MAX + 2048) * 512` |
| Packed struct 對齊 | 正確 | `#[repr(C, packed)]` 搭配 `std::mem::size_of` 驗證，已加上 `zerocopy::Unaligned` 與 `zerocopy::FromZeroes` 保護。 |
| 條件編譯 | 正確 | Linux 下 `fat32-gui` 輸出 stub 訊息並退出；`windows` crate 僅在 `cfg(windows)` 引入。 |

## 五、架構決策記錄

| 決策 | 理由 |
|------|------|
| 分割區類型 `0x0C` | 相容現代 LBA 定址，取代舊 CHS |
| I/O 抽象 `DeviceIO` trait | 讓 `fat32-core` 保持純邏輯，平台讀寫由 GUI 層實作 |
| 條件編譯 `#[cfg(windows)]` | 非 Windows 環境仍可編譯（輸出 stub 訊息） |
| `Mbr::new(partition_sectors)` 傳入 u64 | FAT 計算基於分割區 sector 數，避免 2TB 邊界溢位 |
| 導入 `zerocopy` 庫 | 移除核心資料結構序列化/反序列化中所有潛在記憶體未對齊 UB 與 `unsafe` 區塊 |
